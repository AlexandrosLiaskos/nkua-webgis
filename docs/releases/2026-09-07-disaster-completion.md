# Four-collection delivery evidence

The recovered, agreed roadmap comprises landslides, tsunamis, wildfires and
burned areas, and earthquake impacts. All four have been prepared and published.
The record counts describe source records, not independently deduplicated events.

| Requirement | Implementation and execution evidence |
| --- | --- |
| Reliable, accessible sources and acquisition | `tools/landslides/` and `tools/hazards/acquire_*.py`; acquisition archives retained outside the web root; source citations, provider URLs, reuse terms and limits in each `sites/*/data/manifest.json`. |
| Landslides, three source families | Current manifest contains only UGLC, NASA and Peloponnese families: 1,115,719 point records and 1,006,364 footprint records. Published by `20260907-landslides`, retained by subsequent releases. |
| Tsunami catalogue | Current manifest records 37,027 records from NOAA events, NOAA observations and the Greek impact database. The preparation code retains explicit NOAA event links and original attributes. Final release includes the partial-travel-time correction. |
| Wildfire catalogue | Current manifest records 137,028 EFFIS and MTBS boundaries. Processing retains original geometry attributes, transforms CRS, separates source and derived area, and respects MTBS's declared text encoding. |
| Earthquake impacts catalogue | Current manifest records 15,811 NOAA and USGS records. Preparation preserves source IDs and distinguishes historical impacts, instrumental magnitudes, shaking estimates and modelled potential impacts. |
| Established interface | The generated pages reference shared `lagoons-ui.css`, `common-map.js`, `common-ui.js`, feature-guide CSS/JS and the reusable `hazard-atlas.js`; `collection.py` uses the landslide shell. |
| Source colours, grouping and basemaps | `hazard-atlas.js` uses shared category pins, legends, cluster icons and the same zoom-dependent cluster radii. `common-map.js` supplies the shared basemap picker, default/fallback basemaps and north arrow. Spatial clusters do not assert event identity. |
| Record information and original evidence | `openRecord`, `titleBlock`, `detailSection` and `detailFor` in `hazard-atlas.js` provide record titles, three locator maps, source information, all original attributes, related source records, geometry display and exports. |
| Filters, search and statistics | `applyFilters`, `searchCatalogue`, `renderList`, `openStatisticsGroup` and the shared atlas interface implement the controls. Current manifests provide 12 tsunami, 5 wildfire and 13 earthquake numerical fields; wildfire seasonality uses named categorical months. Landslide numerical datasets and methods remain in its existing application. |
| Definition and other dialogs | Each current HTML file includes the sourced definition, explanation image, shared dialog controls, source library, about content and contribution instructions. CSV and XLSX submission files are generated by the preparation tools. |
| Titles, university branding and sharing | Each current HTML file includes its collection title, canonical URL, Open Graph/Twitter image metadata, favicons and university assets. Separate social artwork is generated by `sharing.mjs`. |
| Homepage image correction | `map-previews.mjs` completed image generation for all four collections. Homepage image paths use JPEG map captures with new version parameters. The final overlay includes all four images and the updated homepage. |
| Publication of all four | The resumed SFTP transfer and final overlay upload returned exit 0. The final publisher returned exit 0, reported WebGIS web started, and printed `Published 20260907-wildfires-earthquakes`. It preserves the preceding landslide/tsunami release while adding the two remaining collections. |
| Preserve existing infrastructure and rollback | `publish-static.py` overlays only site files, preserves the previous static release, records configuration/source backups and recreates only web with `--no-build --no-deps`. It adds collection counter keys without changing the database, API or shared outer proxy. |

## Scope of evidence

The closing audit read the current preparation code, manifests, application
implementation, HTML metadata and publication output. The map captures were
produced as requested image assets. No tests, builds, linters, type checks, git
status/diff checks, visual review or post-publication browser/HTTP checks were
run, in accordance with the workspace instructions. This record establishes
what was implemented and published; it does not claim an independent runtime
test pass or independent scientific validation of every provider record.
